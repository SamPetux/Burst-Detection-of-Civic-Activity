## 5. Фаза D. Детекторы

### D1. Единый интерфейс

- `src/detectors/base.py`: `class Detector: fit_warmup(series: pd.Series) -> None; score(history: pd.Series) -> float` или векторная версия `score_series(series) -> pd.Series` с гарантией причинности (значение в t использует только ≤ t−1). Все детекторы возвращают `score` и `flag` при пороге по умолчанию. Параметр `min_volume` (минимальный абсолютный объём бакета, по умолчанию 5 для часа) общий для всех, чтобы никто не выигрывал за счёт нулевых рядов.
- Тест: `tests/test_causality.py` подменяет будущее случайными числами и проверяет, что `score[:t]` не меняется.

### D2. Робастный z (бейзлайн 1)

- Формула: `z_t = (y_t − med_t) / (1.4826 · MAD_t + ε)`, окно W бакетов; вариант с сезонностью: окно берётся из тех же часов суток за последние K дней (`W_seasonal = K`, K=7).
- Значения по умолчанию: W = 168 ч, порог 3,5; сезонный вариант K = 7, порог 3,5; ε = 1.
- Сетка для D7: W ∈ {72, 168, 336}, порог ∈ {2,5; 3; 3,5; 4; 5}.
- Источник формулы: Iglewicz & Hoaglin 1993 (B7).

### D3. CUSUM (бейзлайн 2)

- Односторонний CUSUM на стандартизованных остатках `r_t = (y_t − μ_t)/σ_t` (μ, σ из скользящего окна W или из сезонного профиля): `S_t = max(0, S_{t−1} + r_t − k)`, сигнал при `S_t > h`, после сигнала сброс. Score = `S_t`.
- По умолчанию: k = 0,5, h = 5, W = 168. Сетка: k ∈ {0,25; 0,5; 1}, h ∈ {3; 5; 8}.
- Источник: Page 1954 (B5).

### D4. STL + остатки (бейзлайн 3)

- `statsmodels.tsa.seasonal.STL(period=24, robust=True)` на скользящем окне последних W часов (причинно: подгонка на истории, остаток текущего бакета по экстраполяции тренда и сезонной компоненты последнего периода). Score = остаток / (1,4826·MAD остатков). Порог 3,5. Эквивалент S-H-ESD (B4) допустим как вариант.
- По умолчанию W = 336, period = 24. Сетка: W ∈ {168, 336, 672}, порог ∈ {3; 3,5; 4}.
- Замечание: STL на 336 точках для каждого шага медленный; кэшировать и обновлять раз в 6 ч при абляции по стоимости.

### D5. TSFM zero-shot (основной метод)

- Модели: `amazon/chronos-2` (основная), `amazon/chronos-bolt-base` (облегчённая), `google/timesfm-2.5-200m-pytorch` (вторая семья; установка из GitHub), `Salesforce/moirai-2.0-R-small` (опционально; лицензия CC-BY-NC, допустима для исследования).
- Протокол: скользящее происхождение (rolling origin) на каждый бакет t: контекст `y[t−L:t]`, прогноз на h = 1 (и h ∈ {3, 6} для абляции задержки), квантили `[0.01, 0.05, 0.1, …, 0.9, 0.95, 0.99]`.
- Score: `s_t = PIT-подобная оценка`: наибольший уровень квантиля q, для которого `y_t > Q_q`, интерполированный между соседними уровнями; при `y_t > Q_0.99` score = 0,99 + `(y_t − Q_0.99)/(Q_0.99 − Q_0.5 + ε)` (чтобы ранжировать превышения). Flag по умолчанию: `y_t > Q_0.99` и `y_t ≥ min_volume`. Это и есть «выход за доверительный интервал вероятностного прогноза» из аннотации.
- Многомерный режим (только Chronos-2): все 8 районов + city как один `predict_df` с одним `id` на ряд в одном вызове (group attention объединяет ряды одного вызова) против отдельных вызовов на ряд. Проверить в документации chronos-forecasting ≥ 2.0, как задаётся группа (аргумент `predict_df` принимает длинный DataFrame; multivariate target задаётся списком колонок `target=[...]`). Запустить оба варианта.
- Контекст по умолчанию L = 336 ч (14 суток); абляция L ∈ {168, 336, 720}.
- Пример кода: `scripts/pilot_chronos2.py` (пилот этой сессии, результат `docs/pilot/pilot_chronos2_hourly.csv`).
- Логировать время на шаг и пиковую память.
- Чего не делать: не дообучать модели (статья про zero-shot); не запрашивать квантили > 0,99 у Chronos-2 (обрезаются).

### D6. Детектор ВКР как «исторический» бейзлайн

- Перенести `detect_bursts_in_series` из civic-monitor-nn (W = 14 дней, z ≥ 2,5, v ≥ 5, σ_min = 1) на суточные ряды; в статье обозначить как «простой z-детектор (ВКР)» с оговоркой §3.2 анализа.

### D7. Протокол настройки порогов (защита от подгонки)

- Два режима отчётности: (R1) «без настройки»: параметры по умолчанию из D2–D5, заданные до просмотра разметки; (R2) «с настройкой»: порог каждого метода подбирается по F1 на первой половине событий по времени и оценивается на второй половине (temporal split), плюс PR-кривые по порогу без выбора точки (AUC-PR).

## 6. Фаза E. Оценка

### E1. Метрики

- Событийные: событие считается обнаруженным, если `flag=True` в ряду соответствующего охвата (city или район события) в окне `[onset − 1 ч, onset + T]`, T = 24 ч (абляция T ∈ {6, 12, 24}). Precision = доля сработок, попавших в окно какого-либо события (сработки одного события в одном окне считаются одной); Recall = доля событий с хотя бы одной сработкой; F1.
- Задержка: `delay = t_first_flag − onset` в часах (для событий с `onset_precision=hour`); отдельно `delay_rel = t_first_flag − first_message_ts`. Отчёт: медиана и IQR по методам, парное сравнение знаковым критерием Уилкоксона.
- Пороговые-свободные: AUC-PR по событийным меткам бакетов (бакет положителен, если в окне события), VUS-PR не нужен.
- NAB-score (M1) как дополнительный, с указанием критики (M2).
- Доверительные интервалы: бутстрэп по событиям (1000 повторов).

### E2. Таблицы и абляции

1. Главная таблица: методы × {P, R, F1, медианная задержка, AUC-PR} для R1 и R2, ряды S1 (город и районы отдельно).
2. Тематические ряды S2.
3. Разрешение 1/3/6/24 ч.
4. Univariate vs multivariate Chronos-2; контекст L.
5. Словарный vs LLM-геопарсер: число видимых районных событий и F1 на районных рядах.
6. Стоимость: секунд на шаг и на полный прогон, память, параметры, нужна ли настройка (да/нет).
- Выход: `docs/results/tables.md` + CSV в `docs/results/`.

### E3. Статистическая проверка «точнее и раньше»

- H1: F1(TSFM) > F1(лучший статистический) в R1. H2: медианная задержка TSFM меньше. Проверять на бутстрэп-ДИ и критерии Уилкоксона по событиям. Если H1/H2 не подтверждаются, это результат статьи, формулировка выводов меняется (`scientific-critical-thinking`).

## 11. Что делать лёгкой модели, если что-то не сходится

- Нет доступа к дампу: все задачи фазы D и E можно отлаживать на `data/series/` из репозитория (138 рядов, окно 27.03–06.05), но отчитываться, что это старый дамп с артефактом.
- Модель не загружается: проверить сеть к HF CDN и `HF_HUB_DISABLE_XET=1`; как запасной вариант `amazon/chronos-bolt-small`.
- Результаты TSFM хуже бейзлайнов: не менять протокол задним числом; записать результат, проверить причинность и калибровку (покрытие квантилей по рядам), затем доложить.
- Нет уверенности в источнике: не цитировать, добавить в `docs/03_sources.md` со статусом «проверить».
